Anyone holding a credential can then prove it is genuine — offline, in under a second, without ever asking the university.

Get started

The vault holds an ECDSA P-256 keypair generated in your browser. The private key never leaves this device — it is not transmitted anywhere, because there is nowhere to transmit it to.

What is real here

SHA-256 digests, ECDSA P-256 signatures and Merkle inclusion proofs all run through the browser's native crypto.subtle. Nothing is simulated. Break a byte and the maths genuinely stops agreeing.

Why a Merkle root

Publishing one root per batch keeps every student record private while still committing to it. A proof for one credential is log₂(n) hashes — about 10 for a cohort of a thousand.

Where a chain fits

The signed header is the only thing that needs an anchor. Writing those 64 bytes to a public chain costs cents and makes the registrar's own history immutable, even to the registrar.

03 — Ledger

Every block remembers
the one before it.

Each header carries the hash of its predecessor, so editing an old record invalidates every block after it. Run the audit, then tamper with a sealed record and run it again.

04 — Verify

Five checks. No phone call.

Paste a passport and the verifier recomputes the credential digest, walks the Merkle path to the anchored root, checks the issuer's signature over the header, and confirms the signing key derives the DID it claims.

05 — Sentinel

Cryptography proves intact.
It cannot prove honest.

A perfectly signed credential can still be fraudulent if the registrar was compromised. Sentinel is a deterministic rule engine over the issuance record — every flag traces to a stated rule, so an auditor can argue with it. No model, no black box, no false confidence.
